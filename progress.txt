## Codebase Patterns
- Next.js 14 with App Router, TypeScript, Tailwind CSS, src/ directory structure
- Path alias: `@/*` maps to `./src/*` in tsconfig
- ESLint config extends `next/core-web-vitals` and `next/typescript`
- Quality checks: `npm run lint`, `npx tsc --noEmit`, `npm run build`
- Dependencies: @supabase/supabase-js, @supabase/ssr, @monaco-editor/react, node-cron, recharts
- `data/sources/` is excluded from tsconfig to prevent cloned repo TS files from breaking typecheck
- Use `Array.from()` instead of spread on iterables (Map, Set) to avoid downlevelIteration errors
- Run scripts with `npx tsx scripts/foo.ts` (tsx installed as devDependency)
- Problem data: 150 problems in data/problems.json; 143 from neenza (clean), 7 premium from krmanik (basic metadata only)
- Join key across repos: LeetCode slug extracted from URL
- Types: import from `@/types` — Problem, UserProgress, AIReviewResponse, SRSResult
- Problem loader: import from `@/lib/problems` — server-side only (uses fs); cached in-process
- Supabase browser client: import `createClient` from `@/lib/supabase/client` (for client components)
- Supabase server client: import `createClient` from `@/lib/supabase/server` (async, for server components/API routes)
- Supabase admin client: import `createAdminClient` from `@/lib/supabase/admin` (service role key, bypasses RLS — for cron jobs only)
- Middleware refreshes auth session on every request; matcher excludes static files
- Dashboard layout: server component checks auth in layout.tsx, client Sidebar component handles navigation/logout/mobile menu
- Dashboard routes: /dashboard, /dashboard/practice, /dashboard/log, /dashboard/progress
- API route auth pattern: `const supabase = await createClient(); const { data: { user } } = await supabase.auth.getUser();` — return 401 if !user
- SRS scheduling: import `calculateNextRevisionDate(score)` from `@/lib/srs` — returns `{ next_revision_date, days_to_add }`
- Submissions API: POST /api/submissions (create), GET /api/submissions (list with ?limit, ?offset, ?problem_id, ?is_self_reported), PATCH /api/submissions (re-score)
- Problem data must be loaded server-side and passed as props to client components (fs-based loader)
- Practice page pattern: server component loads data → client component handles interactivity (state, filtering, search)
- Monaco editor: lazy-load with `dynamic(() => import("@monaco-editor/react"), { ssr: false })` — must disable SSR
- Use `type X = Y` instead of `interface X extends Y {}` to avoid @typescript-eslint/no-empty-object-type lint error
- recharts Tooltip: use custom `content={<CustomTooltip />}` component instead of `formatter` prop to avoid complex TypeScript union types
- Discord webhook: import `sendDiscordEmbed(title, fields, color)` from `@/lib/discord` — handles errors gracefully (logs, never throws)
- Cron auth pattern: check `request.headers.get("authorization") !== process.env.CRON_SECRET` → return 401
- Supabase migrations: SQL files in supabase/migrations/ numbered 001-009 so far (schema.sql has full reference)
- Neon color palette: cyan (#00e5ff), green (#39ff14), purple (#bf5af2) — used across theme
- Problem data now loaded from Supabase `problems` table (not fs) via src/lib/problems.ts using server client
- getAllProblems() orders by leetcode_id; getProblemBySlug() uses .eq("slug", slug).single()
- `supabase/` directory is in .gitignore — use `git add -f` to add supabase files
